## What ran

## Problems found & fixed during the EKS run

1. **EKS access**: creator IAM user was not authorized (401). Fixed by adding an
   EKS **Access Entry** + `AmazonEKSClusterAdminPolicy`.
2. **No default StorageClass / PVC Pending**: EBS CSI was not installed and the
   in-tree `gp2` class was not marked default. Fixed by installing the
   `aws-ebs-csi-driver` addon, attaching `AmazonEBSCSIDriverPolicy` to the node
   role, annotating `gp2` as default, and recreating the PVCs.
3. **Postgres init failed on a fresh EBS mount** (`lost+found` at data dir).
   Fixed by mounting the volume at `/var/lib/postgresql` (data subdir created
   inside the volume).
4. **Bitnami Kafka could not write to the PVC** (non-root image). Fixed by
   adding `securityContext.fsGroup: 1001` to the Kafka StatefulSet.

## Cost & teardown

- Cluster was up for the verification only; `make eks-destroy` removed all 55
  Terraform resources. Three dynamically-created EBS volumes (from PVCs) were
  deleted manually afterwards. No cluster or volumes remain.
- Estimated cost for the ~30-minute run: well under $2.
